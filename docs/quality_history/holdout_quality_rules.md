# Prospective quality rules for the four MELFA candidate records

These rules are fixed before any candidate measurement payload is opened in the signal-extension work. The four members are fixed in `holdout_membership_freeze.json`: position range 0.5 seed 6 and position range 1.4 seeds 0, 5, 10. All four are retained as candidates, including the smaller seed-5 file. File size, agreement with an expected duration, model error and comparison direction do not decide inclusion.

1. **Prerequisite for opening.** The root orchestrator must first freeze all method variants, coefficients, hyperparameter selection, normalization, expected columns and units, signal-window specification, endpoints, aggregation and stopping rules. The full freeze must identify the hashes of this membership record and these quality rules. This metadata audit does not itself authorize opening or evaluating candidate payloads. The root then authorizes one coordinated quality reveal.
2. **Identity.** Verify the unchanged source archive hash and each frozen member's exact path, uncompressed size and ZIP CRC. At the reveal, add the member's decompressed SHA-256 without changing membership. Retain all identity failures and stop use of the affected record until resolved from source evidence.
3. **Schema and finite numbers.** Each record must contain all six required joint columns for `q_filt`, `dq_filt`, `ddq_filt` and `tau_filt`; columns must have aligned row counts, numeric encodings and finite values. Apply this mechanical check to all four before any prediction. Do not compute or expose torque distributions, target-dependent filtering thresholds, residuals, model error or method rankings during quality checking. An invalid value is a logged quality failure, not a license to select favorable remaining samples.
4. **Time and units.** Inspect an explicit timestamp column or source index only during the authorized reveal. Preserve acquisition order. If physical time is used by the frozen method, require a finite strictly increasing time vector or a documented deterministic reconstruction from a source sampling interval and units. Do not infer seconds from `50seconds` in the filename, row count, or apparent signal frequency. Sorting by values or silently repairing reversals is forbidden. A known documented timestamp encoding may be deterministically converted, with the rule and evidence recorded. If physical time is unavailable, a method already frozen in sample-index units may report that scope; do not switch units after seeing outcomes.
5. **Window feasibility.** Apply the exact signal window length, alignment, overlap and minimum-window count from the method/endpoint freeze. A record is eligible if it can form the predeclared required windows. A shorter valid record is included and individually reported; do not lengthen, stitch it to another record, reduce the window or alter the endpoint in response to its length. If no required window can be formed, retain it in the inventory with the mechanical failure reason and report the reduced evaluable count.
6. **Input identity and dependence.** Any input-only overlap or timestamp-continuity check must follow a rule already frozen by the root, run uniformly and precede prediction. Do not choose a record because it is geometrically easy, unusual or favorable. The three shared-seed pairs across amplitude conditions remain same-source dependencies even if exact samples differ. No result is described as a new independent hardware or laboratory acquisition.
7. **Release the complete quality ledger together.** Record pass/fail/unknown for all four members, rows, time provenance, feasible window count and every intervention, while keeping torque values and summaries outside the quality report. Unknown units or identity are unresolved rather than guessed. The root makes the predeclared eligibility decision for all four together. Only after that ledger is frozen may predictive evaluation proceed.
8. **Retain unfavorable outcomes.** Keep every included record in all predeclared method comparisons. Report each record separately and the frozen aggregate; never delete a record, change its weight, change a window or add a new method based on performance. Reused development records do not become confirmation data by holding out unused rows.

The supplied MELFA records used earlier in the project had no `t` column; the earlier converter generated row indices. That historical fact does not establish the time schema or units of these four unopened records. Source metadata and the authorized reveal must resolve this before any time-dependent calculation.
